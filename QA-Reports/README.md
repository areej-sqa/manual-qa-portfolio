# QA Reports

This folder contains sample QA reporting documents demonstrating how I communicate testing progress, execution results, defects, risks, blockers, and overall quality status to product and engineering teams.

## QA Reporting Approach

My QA reporting focuses on providing clear and actionable information, including:

- Testing scope
- Test execution status
- Passed and failed scenarios
- Blocked and pending testing
- Defect status
- Severity and priority
- Bug fix verification
- Known risks
- Testing limitations
- Release readiness information
- Supporting evidence

## Typical QA Metrics

Depending on the project, QA reports may include:

- Total test cases
- Passed
- Failed
- Blocked
- Pending / Not Run
- Pass percentage
- Total defects
- Defects by severity
- Defects by status
- Reopened defects
- Verified fixes
- Remaining risks

## Reporting Principles

QA reports should:

- Clearly distinguish facts from assumptions
- Avoid hiding failed or blocked testing
- Document testing limitations
- Identify unresolved risks
- Link defects to affected functionality
- Provide evidence where necessary
- Avoid claiming unexecuted tests as passed
- Give stakeholders enough information to make informed release decisions

> All QA reporting examples in this portfolio are fictional and created for demonstration purposes. No confidential customer, employer, project, or production information is included.
